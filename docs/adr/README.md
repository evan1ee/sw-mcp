# Architecture Decision Records

ADR-001 to ADR-033 were taken in specification v1.9 (section 19); ADR-034 to ADR-039 were added in v1.10 to settle the toolchain before Phase 0; ADR-040 in v1.11; ADR-041 and ADR-042 in v1.12; ADR-043 to ADR-047 in v1.13; ADR-048 and ADR-049 in v1.14. IDs are stable and match every `ADR-NNN` mention in the docs. Decisions marked **[Builder's call]** were made while writing the specification, not by the owner, and may be revisited.

New decisions: copy [template.md](template.md), take the next free number, and add a row here.

| [ADR-013](ADR-013-tolerances-in-drawing-intent-ir.md) | Tolerance values live in the Drawing Intent IR; Design Intent states the requirement they serve | One owner per value; P0 needs no derivation engine | Accepted |
| [ADR-014](ADR-014-drawing-checks-read-back-actual-annotation.md) | Drawing checks read back actual annotation geometry | "Done" is verified, not assumed | Accepted |
| [ADR-015](ADR-015-iso-only.md) | ISO only, via standard files and profiles | One standard done well; others addable later | Accepted |
| [ADR-016](ADR-016-solidworks-2025-only.md) | SOLIDWORKS 2025+ only | Newer annotation APIs; smaller test matrix | Accepted |
| [ADR-017](ADR-017-phase-1-ir-built-and-hand-modelled-parts.md) | Phase 1 drawings accept IR-built and hand-modelled parts, with a stopgap reference scheme | Owner's real parts are hand-modelled too; full semantic references arrive in Phase 2 | Accepted |
| [ADR-018](ADR-018-feature-coverage-tiered-by-benchmark-need.md) | Feature coverage tiered by benchmark need; Create vs Read support; generic dimension read | Cover what real parts and drawings need without implementing every SOLIDWORKS feature | Accepted |
| [ADR-019](ADR-019-features-are-ir-data-not-tools.md) | Features are IR data, not MCP tools; toolsets and on-demand schemas | Coverage grows without growing per-turn token cost | Accepted |
| [ADR-020](ADR-020-drawing-completeness-functional-determinacy.md) | Drawing completeness = functional determinacy, with parameter coverage as proxy | Modeling dimensions are not manufacturing dimensions; 1:1 parameter coverage passes useless drawings and fails good ones | Accepted |
| [ADR-021](ADR-021-language-independent-feature-identity.md) | Identify features and planes language- and rename-independently | Feature and plane names are localized and user-editable | Accepted |
| [ADR-022](ADR-022-never-modify-source-parts-without-permission.md) | Never modify source parts without permission; respect read-only and PDM | Drawings must not have side effects on released models | Proposed — Builder's call |
| [ADR-023](ADR-023-split-dimension-scheme.md) | The dimension scheme is split: authored entries (`critical_dimensions`, `scheme_overrides`) live in the Drawing Intent IR; the pipeline-owned Resolved Scheme holds the full derived result; the Layout IR only places it | Checks D4–D6 need one record of what is dimensioned; engineer overrides survive regeneration; regenerating does not bump the intent revision or make agents resend derived data (revised in 1.9) | Proposed — Builder's call |
| [ADR-024](ADR-024-requirements-target-functional-features.md) | Requirements target functional features; Part Feature Graph nodes declare what they `realize`; existing parts get a read-only Part Feature Graph | Keeps the intent independent of modeling strategy; one path for IR-built and hand-modelled parts | Proposed — Builder's call |
| [ADR-025](ADR-025-drawing-intent-as-drawings-and-pmi.md) | Drawing Intent IR emitted as drawings (P0) and as PMI (P2) | One specification, two outputs | Proposed — Builder's call |
| [ADR-026](ADR-026-task-driven-ir-composition.md) | Task-driven IR composition: shared core plus optional, independently usable modules; a task submits only the modules it needs as an IR bundle | Simple part requests stay simple; assemblies, requirements and drawings are added only when the task needs them | Accepted |
| [ADR-027](ADR-027-design-intent-ir-optional-for-drawings.md) | Design Intent IR optional for drawings (fallback to part properties and Drawing Intent `context`); implemented in Phase 3 | Keeps Phase 1 small; Design Intent arrives when requirement checks consume it | Proposed — Builder's call |
| [ADR-028](ADR-028-in-process-solidworks-add-in.md) | The C# executor runs in process as a SOLIDWORKS add-in, with local IPC to Python | Cross-process COM is too slow for drawing read-back; the add-in gets SOLIDWORKS's STA thread and document events | Proposed — Builder's call |
| [ADR-029](ADR-029-phase-1-is-read-first.md) | Phase 1 is Read-first: Tier 1 Read for every feature, Create only for what the IR-built benchmark parts need | The drawing pipeline works mainly on hand-modelled parts; keeps Phase 1 within the anti-overengineering goal | Proposed — Builder's call |
| [ADR-030](ADR-030-phase-1-increments.md) | Phase 1 ships as 1a (checks on existing drawings), 1b (pipeline on hand-modelled parts), 1c (IR-built parts); the reference implementation runs alongside until parity at the end of Phase 2 | Puts the riskiest, most valuable part (read-back and checks) first; removes reference parity from the Phase 1 critical path without losing capabilities | Proposed — Builder's call |
| [ADR-031](ADR-031-drawing-geometry-snapshot.md) | Checks run on a versioned Drawing Geometry Snapshot, separate from the Layout IR | The Layout IR holds positions, not line and text geometry; one recorded format serves checks, offline tests, benchmark replay and report evidence | Proposed — Builder's call |
| [ADR-032](ADR-032-python-owns-jobs.md) | Python owns jobs, lifecycle and journal; the add-in is stateless apart from completed operation IDs; IPC commands are coarse; the pipe is user-only with a session token | A crash on either side has a defined outcome; IPC cost stays bounded; other local processes cannot drive SOLIDWORKS | Proposed — Builder's call |
| [ADR-033](ADR-033-plain-file-project-store.md) | Project store of plain files; parts identified by PDM ID or path plus fingerprint, never by writing into them; lost state makes annotations pinned, not movable | Keeps ADR-022; survives moved files; never loses an engineer's edits | Proposed — Builder's call |
| [ADR-034](ADR-034-python-toolchain.md) | Python toolchain: CPython 3.13, uv workspace, official MCP SDK, generated Pydantic models, ruff, pyright strict, pytest | One lockfile across packages; typing catches IR misuse before a live run | Proposed |
| [ADR-035](ADR-035-json-schema-contracts.md) | JSON Schema 2020-12 files in `schemas/` are the source of truth; Python and C# types are generated from them | One language-neutral contract for validator, agents and both languages | Proposed |
| [ADR-036](ADR-036-ipc-protocol.md) | IPC: one user-only named pipe per session, length-prefixed UTF-8 JSON frames, JSON-RPC 2.0 messages, versioned handshake with session token | Simple in both languages, replayable, fast enough for coarse commands; A1 measures it | Proposed |
| [ADR-037](ADR-037-error-model.md) | One error catalogue with domain-prefixed codes; one MCP response envelope; failed checks are results, not errors | Agents branch on stable codes, not prose | Proposed |
| [ADR-038](ADR-038-csharp-add-in-build.md) | SDK-style net48 x64 projects; SOLIDWORKS-free Core; interop referenced from the install; per-user registration; analyzer bans unsafe APIs | Most C# testable without SOLIDWORKS; no vendor binaries in the repo | Proposed |
| [ADR-039](ADR-039-monorepo-and-ci.md) | One `sw-mcp` repository; languages by folder; hosted CI for everything SOLIDWORKS-free, self-hosted CI on the licensed machine for live suites | Contracts and both sides change together; the licensed machine runs only what needs it | Proposed |
| [ADR-040](ADR-040-verb-first-tool-names.md) | MCP tools are named `<action>_<object>`; names that would equal a reference tool change their object word, so file tools are `*_cad_file` | Owner preference; the CI clash check keeps coexistence (2.4) safe | Accepted |
| [ADR-041](ADR-041-core-service-topology.md) | One long-lived Python core service per user owns tools, jobs, journal, store and add-in connections; MCP servers are thin stateless stdio front-ends | Jobs outlive agent clients; several agents share one queue; keeps ADR-032's single owner | Proposed |
| [ADR-042](ADR-042-contract-compatibility.md) | One compatibility policy for IR, artifacts, MCP tools, IPC, configuration and store: minor = additive, strict readers for authored input, migrate on read, deprecate before removal, CI-enforced | One rule set across contracts; stores outlive releases | Proposed |
| [ADR-043](ADR-043-jobs-over-mcp.md) | Jobs return an execution ID; results by polling `get_execution_status` with long-poll `wait_ms`; progress notifications optional; MCP tasks not used in Phase 1; 7-day retention | Works in every client; jobs independent of the connection | Proposed |
| [ADR-044](ADR-044-mcp-protocol-baseline.md) | MCP revision 2025-06-18 minimum; structured output with `outputSchema` and a one-line text summary; reports, snapshots, modules and schemas as resources; no prompts, sampling, elicitation or roots | Exact shapes for agents and tests; bulk data on demand | Proposed |
| [ADR-045](ADR-045-solidworks-version-compatibility.md) | Build against the oldest supported SOLIDWORKS; newer APIs only behind named capabilities; versions admitted by passing the benchmark | Version-dependent behavior explicit and tested | Proposed |
| [ADR-046](ADR-046-document-ownership-and-outputs.md) | Jobs close only documents they opened; save only on COMMITTED; failed output to `.failed.SLDDRW`; overwrite only drawings the store proves the system produced, with backups | Never closes, saves or overwrites the engineer's work | Proposed |
| [ADR-047](ADR-047-test-data-custody.md) | Benchmark binaries in Git LFS; holdout parts only on the SOLIDWORKS CI machine under owner control; only aggregate holdout results published | Versioned test data; a holdout set that stays unseen | Proposed |
| [ADR-048](ADR-048-ir-passing-and-patches.md) | Identified items are kept in objects keyed by ID; documents are created by value, changed by RFC 6902 JSON Patch, and referenced everywhere else | Tokens proportional to the change; standard patch tooling; pinned job inputs | Proposed |
| [ADR-049](ADR-049-reference-resolution-split.md) | The add-in gathers geometry candidates in one call; Python resolves, scores and pins; the add-in dereferences and re-checks at execution | Respects coarse commands; decisions testable offline and replaceable in Phase 2 | Proposed |
